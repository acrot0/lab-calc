## 安装到手机

从这一版起可以装到主屏当应用用。装法按平台给：Chromium 系（Chrome / Edge）点应用里出现的安装按钮，走系统原生弹窗；iOS 和 iPadOS 没有那个事件，给的是 Share → 添加到主屏幕 的分步说明；没有安装途径的浏览器不显示任何东西。关掉过一次就不再问。

装完是全屏运行，所以这一版补齐了三件只有装上才会暴露的事：状态栏和底部手势条会压住页面（`viewport-fit=cover` 之前是缺的，`env()` 的 inset 一直读不到，CSS 静默失效）；系统返回手势会直接退出应用、连带丢掉表单里刚敲的东西（现在每开一层压一条历史）；结果面板的入场动画只在本次会话第一个结果播一次，之后每次都是硬切（动画挂在 `.result-main` 上，而 CSS 动画只在挂载时跑）。

## 能算得出东西的算术

三次输入，人写出来毫无疑问，这里全是语法错误：`2**10`、`1,000`、`mod`。现在都收。`**` 归一成单个 `^` 而不是加第二个运算符，优先级只有一个幂运算要想，两种写法也不会漂移。千分位只认严格分组形式——`1,234,567` 可以，`1,00` 仍是语法错误而不是被悄悄读成 100，欧陆写法（`1.000,5`）故意不猜，猜错比拒绝更糟。`%` 仍然是百分号：实验台计算器里末尾的 `%` 意思是百分之一，`0.9%` 是 0.009 的浓度，把它改成取余会为了一个用得少得多的运算废掉所有百分比输入。

计算器的键盘之前够不到解析器认得的多数东西。现在两页函数键，数字、括号、清除和退格在不翻页的那块上，另加了逗号键——没有它 `hypot(`、`min(`、`max(`、`atan2(` 打开的调用在手机上（屏幕上那块键盘是唯一的键盘）根本没法收尾。

## 粘贴进去能算了

「计算器还是不能粘」报了两次。粘贴本身一直是好的——字符到了，输入框也显示了——然后解析器拒绝它们，读起来就是拒绝粘贴。五个独立原因，全都由复制粘贴触发：

- **排版符号**。没人手打 `×`，都是从 Word、幻灯片、Excel 单元格或 PDF 里复制来的，而那些都会替换成排版形式。`×`、`÷`、U+2212 和整个破折号家族（en / em / figure / horizontal bar）此前逐个报「无法解析」。另外还有粘贴表格单元格里满是的不换行空格和细空格。
- **全角字符**。中文输入法默认就产出 `１２＋３`，在输入框里和 ASCII 看不出区别。
- **上标**。`cm²`、`10⁻³` 是每本教科书写单位和幂的方式。现在改写成 `cm^2` 和 `10^-3`——**故意不走** `String.normalize('NFKC')`，它把 `²` 映射成普通 `2`，会把 `2²` 变成二十二。
- **数字框静默截断**。`readNumberField` 先问 `looksLikeExpression`，回落到 `Number.parseFloat`，而它在第一个非数字处停下：从表格粘来的 `1,234.5` 变成 **1**，没有报错，框子看起来是填好的。现在求值器先说话，回落改成严格的数字字面量判定——`parseFloat('1,00')` 是 1，`parseFloat('0x10')` 是 0，被求值器拒绝的东西被部分解析，是这个应用能有的最坏故障。
- **换算器提供而计算器拼不出的单位**。标识符规则只认 ASCII，于是 `µg`、`µm`、`Å`、`Ω`、`kΩ` 在表达式里全部读不出来，而在换算器里工作正常。一个单位在半个应用里能用、在另一半里报「无法解析」，比缺了它更糟，因为故障看起来像打错字。

顺带查出并修掉的：`1 °C` 曾被当成系数为 1 的单位接受（拒绝逻辑拿符号去比一张以 ASCII 形式 `K/C/F/R` 为键的表，而单位注册表里还有排版形式的 `°C` 和 `°F`——静默错答比它替换掉的解析错误更糟，现在按量纲判定）；`1 deg` 和 `1 turn` 抛裸 TypeError（`ratio` 和 `angle` 按设计没有指数向量，`EXPONENTS[dim]` 是 `undefined`，第一次运算就抛 "Cannot read properties of undefined"，英文且没有错误码，无法翻译）；`10^-3 M` 被拒为「指数必须是纯数字」，因为指数解析吞掉了单位——而 `10ˣ` 那个键正是为这个序列加的。

动手前先量过：mathjs 同样拒绝全部五个粘贴用例，且压缩后 654 KB。问题从来不在语法。

## 分子生物学：第一批非化学计算

十五个页签此前全是化学，生物实验室每天要做的算术根本不在里面——而它恰恰是最容易在下午六点一手移液枪的情况下算错的算术。九个计算，每个都是一个比值：

- **核酸浓度**（A260），系数作为**参数**而不是常量。50/40/33 µg/mL 分别对应 dsDNA、RNA 和 ssDNA/寡核苷酸，对寡核苷酸用 50 会把产量高估一半。光程和稀释都做了校正——NanoDrop 的短光程正需要这个。
- **纯度比** 260/280 和 260/230，给一个**刻意粗糙**的判断。比值分不出「一点苯酚」和「很多苯酚」，一个被呈现为诊断的数字比一个被呈现为数字的数字更糟。分母为零返回 null 而不是 Infinity，因为空白没有比值，而 Infinity 是表格会打印出来的数。
- **稀释到目标浓度**，返回**体积**而不是倍数——倍数不是用移液枪量的东西。
- **寡核苷酸摩尔浓度**，这是质量系数不适用的地方：寡核苷酸的吸光度取决于序列，所以只有 A260 给不出摩尔浓度，函数在没有序列时拒绝计算。用残基质量和标准的 0.9 减色性校正。
- 接种体积、**倍增时间**（下降时抛错而不是返回负倍增时间——那是细胞死亡，另一个现象）、RPM↔RCF，以及 **k 因子**——指定离心的半径无关方式，因此是唯一能在转子之间通用的方式。
- **米氏方程用 Hanes–Woolf 而不是 Lineweaver–Burk**：后者除以 v，最噪的测量（最小的速率）得到最大的权重。拟合结果对照已知参数生成的数据做过检查，并报告 r²，让不描述数据的拟合可见。

**酶动力学曲线**也画出来了。三个数字的表格看不出一个测定最要紧的事：底物范围到底有没有跨过 Km。五个点全在 Km 以下也能拟合出看起来很有底气的参数，而数据里几乎没有关于 Vmax 的信息。每个测量点都画一条到拟合曲线的竖线——那段**就是**残差，也是画数据而不是只画一条线的理由。Km 和 Vmax 标成虚线参考，是否落在测量范围内可以直接看出来而不是靠推断。

## 模型开始校正活度、离子强度和温度

教学须知从第一个版本起就写着这三项被忽略。现在不是了，须知也换成了更窄的说法。

- **温度**按积分后的 van 't Hoff 关系。pKa 随温度移动，移动幅度在本应用提供的缓冲液之间差两个数量级：醋酸在 25 → 20 °C 漂移 0.002 个单位，Tris 在 25 → 4 °C 漂移 0.12 和 0.63。每种缓冲液一个数字的表格，对 Tris 的错超过它的可用范围。
- **离子强度**从配方推导而不是问用户。溶液是电中性的，所以反离子就是平衡缓冲液自身带电物种的那个——对磷酸盐来说，那个反离子是 I 的最大单一贡献者。只数缓冲液自己的离子会把 I 低估 1.6 倍。
- **活度**按 Davies，用在弱酸求解和 Henderson–Hasselbalch 两处。

值得记下来的发现来自测试而不是设计：**中性弱酸的校正会抵消**。γ_H = γ_A，所以醋酸在 I = 0 到 0.1 之间只移动 0.0008 个单位。模块返回这个答案而不是制造一个偏移，因为一个把醋酸「校正」0.05 的计算器会教出错误的机理。它真正修的是带电酸——磷酸的 pKa2 溶液在实验台浓度下移动 0.38 个单位。

**局限性须知拆成了两栏。** 一个低估自己的须知是另一种不实：它教用户去怀疑一个比他们以为的更好的数字。一栏是校正了什么、校正在哪有效；另一栏是没有任何页签建模的东西——CO₂ 溶解、混合体积收缩、杂质与络合，以及非缓冲体系的 pH 和所有滴定曲线（仍是理想溶液解）。README 长成同一张表，并给出校正实际产生的数字：Tris 在 4 °C 从 7.37 移到 8.08，磷酸盐在 I = 0.2 移动 −0.38。

## 首个界面只装首个界面

实测：画出默认页签此前要 236 KB（gzip 后），现在 186 KB。整个应用在一个包里，所以打开它要在第一个输入框出现之前下载并解析全部十六个页签——带 SMILES 渲染器的周期表、两个 canvas 图表页签、打印报告，以及一个手写的 ZIP-of-XML 表格写入器。手机上这是「计算器能打开」和「打不开」的区别。

十六个分块，每个 0.9–12.6 KB。打印报告在面板挂载时加载而不是打印时——打印对话框不会等网络请求，等分块到了页面已经进打印机了，空白。`.xlsx` 写入器按需加载，失败时会说明而不是静默什么都不做。顺带删掉 `lucide-react`（磁盘上 33.7 MB，源码里零引用）。

## 主题与图表

**又加了四套配色**：Gruvbox 和 Solarized，明暗各一，六套变十套。两套都从各自的包读取而不是抄写。检查后否决了三个包，理由写在文件里：Nord 的 `(Apache-2.0 AND CC-BY-SA-4.0)` 会把 share-alike 附着到这个 MIT 分发上；`solarized-colors` 的 `index.js` 是 gruvbox 十六进制值逐字复制后冠以 Solarized 文件名；npm 上的 `base16` 是同一份陈旧 gruvbox 副本的第三个名字。

**每个主题现在画自己的图表颜色。** 每个 canvas 图表都接一个 `theme` prop 然后去一张只有两个条目（`dark` 和 `light`）的表里查——但 prop 传的是配色**键名**，于是十套配色里有八套两边都不匹配、落到暗色默认值。Catppuccin Latte 上的图表在奶油色卡片上画白色网格。之所以一直没被发现，是因为那张表恰好含有的两个主题正是所有人手工检查的那两个。现在颜色从配色自身的 token 推导，没有需要记得更新的清单。等当点标记也不再使用警告色——它不是警告，是同一个量的第二种读法，一个正确的滴定看起来像出了问题是要发错信号。

**空的右栏回来了，而且现在有测试。** 把分栏移进 `Card.jsx` 时重新引入了容器查询此前修掉的那个缺陷：只要页签**有** `Result` 元素就渲染结果栏，而没有值 `Result` 什么都不渲染——于是十五个页签里有十个长期挂着空白的右半边。

## 修掉的其它

- **计算器窗口会黏在光标上，且可能被扔到屏幕外拿不回来。** 三个拖拽缺陷，全是靠真鼠标驱动（而不是合成事件）才找出来的。`setPointerCapture` 调在窗口上，而 move 和 up 处理器绑在标题栏上；捕获把该指针后续所有事件重定向到窗口，所以 `pointerup` 从没到达标题栏，`drag.current` 从没被清掉，窗口之后在普通悬停时也跟着光标跑。另外抓取边距是 48px，而标题栏右端是 DEG/RAD 开关和关闭按钮——在左边缘，整条可见带就只有关闭按钮，在屏幕上、看起来够得着、完全推不动。边距改成 120px，边距测试也改成对照它必须让开的控件宽度，而不是断言那个数字。
- **右栏布局不再跳。** 卡片本来是单个 grid，结果靠 `grid-column` 放进第 2 列，而 **CSS Grid 跨列共享行高**——282px 的结果把第 1 行撑高，于是本该紧跟字段下方的主按钮被结果的全高推下去。实测：每次计算按钮移动 212px。这不是调 grid 能解决的，共享行就是 grid 的定义。现在拆成两个流上下文，按钮移动 0px。
- **计算器不再自己关掉。** 它待在一层全屏 scrim 后面，而 scrim 唯一的职责是把它关掉——那是模态的行为，而这个窗口刻意不是模态。它存在的意义是**一边**填后面的表单**一边**算数，而点进输入框第一下就把它关掉的 scrim 恰好让这件事没法做。scrim 已移除。
- **材质开关已移除。** 在开了「减少透明度」的机器上它永久禁用——这是对的，一个要求减少透明度的用户不该被一个自以为更懂的应用塞回更多透明度。但一个永远置灰的控件和一个坏掉的按钮无法区分，而它被当成后者报了上来。诚实的修法不是做个更好的禁用态，而是停止提供一个操作系统已经替你做完的选择。
- **返回手势关掉的是层，不是应用**；**状态栏和手势条不再压住页面**；**结果入场动画每次都会重播**（详见开头「安装到手机」一节）。
