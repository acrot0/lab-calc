## 1.2.0：底栏可以自己排了，手机计算器不再弹输入法

上一版补的是「步骤顺序」。这一版补的是**你自己怎么用**——把常用的放在手边，
以及修掉手机端最挡路的那个东西。

### 导航可以自定义

底栏显示哪几个功能、按什么顺序，现在由你决定。

**手机和电脑共用一份顺序。** 在手机上把「分光光度」拖到第一位，换到电脑上侧栏也是第一位。
不是两份设置——存的是全部 20 个功能的顺序，手机取前几个，电脑显示全部。

**编辑方式**：手机端「更多」→「编辑底栏」；桌面端侧栏底部。

- **拖动排序**：按住手柄拖动，行会实时让位。
- **键盘也能排**：回车拿起 → 方向键移动 → 回车放下 → Esc 还原。
- **底栏项数可选 3–5 个**：再多每个按钮就小于手指能点准的尺寸了。

**没有任何功能会被藏起来。** 底栏之外的都在「更多」里。这个设计的目的是把你常用的
放到前面，不是让某些功能消失。

### 手机计算器不再弹输入法

「计算」页签的输入框，在触屏设备上改为**只读**，下方接上完整的计算器键盘——
和桌面端浮动计算器是同一套按键。

之前的样子：点输入框 → 系统输入法弹出 → 盖住屏幕下半部分，**包括你点它就是为了看的结果**。

键盘默认收起函数区，只留数字、运算符、内存和 `=`——全键盘 574px 会把输入框挤出屏幕，
收起后 361px，输入框、结果、键盘同屏。需要 sin/cos 时点「函数」展开。

桌面端不受影响：那里有硬件键盘，输入框仍然可以直接打字。

### 三个拖动排序的缺陷

手机端拖动时行会重叠。查下去是三个独立原因，都是 1.1.0 引入的：

1. **行处理器被当成了工厂函数**——React 拿事件去调用它，行索引变成了一个事件对象，
   被拖的那行永不位移，邻居却照常让位。
2. **格距量错了基准**——用变换后的位置量，而拖动全程行都带变换，每帧量出来都不同。
3. **`translate3d` 参数个数错**——非法值不报错，浏览器静默丢弃整条声明。

第三个最难找：没有异常、代码路径正常执行，只有像素是错的。最后靠
`CSS.supports('transform', …)` 定位。

### 另外修的

- **手机端「编辑底栏」列表滚不动**——行上的 `touch-action: none` 阻断了触摸滚动，
  手指落在行上（占 92% 面积）浏览器不启动滚动。而它本来就不需要：拖动只从手柄开始。
- **偏好写入执行两次**——写在 `setState` 的更新函数里，React 严格模式会调用两次。

### 全部实测

- 测试 **2603 通过 / 127 文件**（上一版 2514）
- 三个平台 CI 全绿；`npm run verify` 含署名检查（作者只有 acrot0）
- 20 个页签在浏览器里逐个点过示例、点过计算：零报错、无空值、无横向溢出
- 拖动排序在真实触摸下实测：无重叠、放下后无残留变换、顺序正确
- 手机端 390×844 与桌面端 1440×900 均实测
- 导出实测：CSV / Markdown / JSON / 存为图片（PNG）全部可用
- Markdown 导出含出处表头、模型边界说明与配方卡
- `prefers-reduced-motion: reduce` 下动画全部关闭，保留淡入替代
