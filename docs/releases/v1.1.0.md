## 1.1.0：四个配制页签现在会画出「先做什么，后做什么」

上一版让记录留得下来。这一版补的是记录里最容易漏掉的一件事：**顺序**。

配溶液是一步错就全废的事。步骤文字一直都在——Markdown 导出和打印报告里的编号列表。
但编号列表说不出「第 2 步依赖第 1 步」：它读起来像四件并列的事，而不是一条链。

### 操作步骤流程图

称量配制、稀释、缓冲液、梯度稀释四个页签，算出结果后可展开一张流程图：每步一个方框，
箭头连接，按顺序向下。

方框左侧的色条标出步骤类别（称量 / 转移 / 调节），扫一眼就能找到称重那一步，
不用读完全部。图可导出为独立 SVG——配色已内联，不依赖本应用，能直接贴进实验记录本。

只给这四个页签。只有这四类计算真的是**手上的动作**；给能斯特方程编一套步骤，
编出来的东西会有人照着做。

### 批量缩放

一条已保存的配方可以按倍数重算成**新记录**：0.25× / 0.5× / 2× / 5× / 10×。

原记录不动——这是刻意的。要的是「同一份配方换个规模」，不是「把原来的改掉」。
新记录带 `scaledFrom` 字段，说明它从哪条、按什么倍数来。

**浓度不缩放**。缩放的是体积和由此算出的质量：500 mL 的 0.5 mol/L 配方按 2× 变成
1000 mL、29.22 g，而 0.5 mol/L 保持不变。把浓度也乘 2 会得到一份完全不同的溶液，
那不是缩放。

### 同一屏里同一个量印出两种精度

实测发现的老问题：结果面板的主数字和它下方的 ± 行，有时按不同位数修约。
渗透压显示 `743.687 kPa`（6 位有效）而标题是 `3.6698 atm`（5 位）——同一个量，
同屏两个精度。

原因是两处各自修约。现在统一由结果面板决定有效位数，`test/result-precision-consistency.test.mjs`
会扫描全部 20 个页签的 `Result` 元素，两处不一致就 fail。

### 界面

- **表单卡片与历史栏宽度不一致**：宽屏下两者宽度由内容决定，算与不算之间卡片会跳
  237px。宽度移到网格轨道上，不再依赖卡片内容，实测跳动为 0。
- **手机端记录面板标题栏**：窄屏下标题被挤断成两行。

### 提醒

**本工具仅供教学与学习**，不可用于临床、诊断、生产或任何有法规要求的场景。
活度校正只在 I ≤ 0.5 mol/L 内可信；CO₂ 溶解、溶剂体积收缩、络合平衡都未建模。
任何实际配制前，请与教材、药典或试剂说明书**对照核对**。
