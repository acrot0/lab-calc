## 2. 实测发现（本次会话，2026-09-29）

### 2.1 ⚠️ 安卓端导出极可能完全不可用 —— 本计划最重要的一条

**置信度 HIGH**，但**尚未在真机上跑过**（§3.4 是验证步骤）。

| 查证项 | 结果 |
|---|---|
| Capacitor 7.6.9 源码搜 `DownloadListener` | **0 命中** |
| `BridgeWebViewClient.shouldOverrideUrlLoading` | 只处理路由，不处理 blob |
| `MainActivity.java` | **5 行**，空 `BridgeActivity` 子类，无任何 Java 代码 |
| 导出实现 | **唯一一处** `downloadFile()`（[export.mjs:616](src/ui/export.mjs#L616)），三端共用 |
| FileProvider / `file_paths.xml` | 已声明，但**无任何代码使用** |
| 安卓导出测试 | **0 个**（`test/` 里只有 `android-version-code.test.mjs`） |
| 社区实证 | [Capacitor #5478](https://github.com/ionic-team/capacitor/issues/5478)：「Android 上没有报错，文件也找不到」 |

**为什么这比它看起来严重**：`downloadFile()` 用的是
`Blob` + `URL.createObjectURL` + `<a download>` + `click()`。这套 API 在
Android WebView 里**没有原生下载通道**——WebView 不实现 `download` 属性，
既不报错也不保存。而导出是**唯一的数据出路**：记录都在 localStorage 里，
用户唯一的备份手段就是这个按钮。

**如果它在手机上不工作，「每次计算自动留存」的完整承诺在移动端就成立不了**——
用户能存但不能取。而移动端恰恰是这个应用的主平台。

### 2.2 写失败完全静默

`saveHistory()` 在写入失败（配额满、Safari 无痕）时 **返回 `false`**，
但 [App.jsx:326](src/ui/App.jsx#L326) 忽略返回值，全应用无一处 surface 它。

结果：**用户的历史在某次写入后停止增长，界面上没有任何迹象。**
新记录照常出现在列表里（因为 React state 是它自己的），
但刷新页面就没了 —— 而用户不会知道是这个原因。

### 2.3 墓碑无上限

`saveHistory()` 用 `if (e.deletedAt) { out.push(e); continue; }` 保留**全部**
已删记录，不设上限（[history.mjs:101](src/ui/history.mjs#L101)）。

实测计量（本机跑）：

| 项 | 值 |
|---|---|
| 单条记录 JSON | 342 B |
| 单条 tombstone | 381 B |
| 500 条 live（现行上限） | 167 KB |
| 10 次「清空全部」后总量 | ≈ 5500 条 / **2.0 MB** |

localStorage 配额约 5 MB。**瓶颈是墓碑，不是活记录**——
10 次清空就吃掉 40%，而清空全部是列表里最显眼的按钮。

### 2.4 免责声明 5 条，没有一条提数据存续

`DISCLAIMER_POINTS` 覆盖：教学用途 / 不可用于临床 / 模型是简化的 /
请自行核对 / 结果带不确定度。**没有一条说记录存在哪、什么时候会丢。**

首次运行是用户注意力最集中的时刻，而这句话不在那里。

### 2.5 iOS ITP 会删掉全部本地存储（7 天）

WebKit 官方文档：**7 天无用户交互**后，ITP 删除全部 script-writable storage ——
localStorage、IndexedDB、Service Worker 注册与缓存**全部**。

**关键**：`navigator.storage.persist()` **无法豁免**这条规则 ——
WebKit 明确拒绝了要求豁免的 PR，理由是
「`StorageManager.persist()` 不应用来覆盖 ITP 政策」。
**只有「添加到主屏幕」的 Web App 才是豁免的。**

而当前安装提示的文案是「装到桌面或主屏幕后可以离线使用」——
**说的是次要理由，真的理由（iOS 上不装就在 7 天后丢数据）没说。**

### 2.6 无障碍：canvas 图表无文字替代

8 处 `<canvas>`（5 个独立 Plot 组件 + CurveTab + SpectroTab），
**全部无 `aria-label` / `role` / 文字摘要**。`test/` 里无任何无障碍测试。
这是 v1.4.0 的范围，此处只记录实测状态。

## 3. 安卓导出的修法对比

### 3.1 三种修法

| | 方案 A（推荐） | 方案 B | 方案 C |
|---|---|---|---|
| **做法** | `@capacitor/filesystem` 写 base64 到 Cache，再 `@capacitor/share` 调系统分享 | `@capgo/capacitor-file-sharer` 的 `save()` | 自写 Kotlin：`DownloadListener` + `JavascriptInterface` |
| **原理** | FileProvider + `ACTION_SEND` Intent，**完全绕开 WebView 下载通道** | MediaStore 写入，**真存进系统 Downloads** | 拦截 blob URL，base64 桥回原生解码落盘 |
| **新增依赖** | 2 个（Capacitor 官方，MIT） | 1 个（第三方，**MPL-2.0**） | 0，但 ~150 行原生代码 |
| **版本匹配** | filesystem `7.1.8` / share `7.0.4`（peer `>=7.0.0`） | `8.1.10`（跟随大版本） | 不适用 |
| **Android 11+** | ✅ Cache 是应用私有目录，无 scoped storage 问题 | ✅ MediaStore 是官方推荐路径 | ⚠️ 落 Downloads 需 MediaStore 或 `ACTION_CREATE_DOCUMENT` |
| **Web/桌面影响** | 需平台分支：native 走插件，web 走现有 `downloadFile` | 同上 | 无（原生代码不进 web bundle） |
| **许可门禁** | ✅ MIT 在 ALLOWED | ⚠️ **MPL-2.0 在 REVIEW 集**（不拒绝，但要人工过一遍） | ✅ 无新依赖 |

**已实测确认的依赖事实**（`npm view`）：

```
@capacitor/filesystem       license=MIT      version=8.1.3   （7.x 最新 7.1.8）
@capacitor/share            license=MIT      version=8.0.2   （7.x 最新 7.0.4）
@capgo/capacitor-file-sharer license=MPL-2.0 version=8.1.10
capacitor-blob-writer       license=MIT      version=1.1.20  （无 Capacitor 7 版本，排除）
```

### 3.2 推荐 A，理由

1. **两个插件都是 Capacitor 官方一方**，与 `@capacitor/core` 同源、同版本线，
   升级路径一致。B 是第三方（Capgo），要跟它的发布节奏。
2. **MPL-2.0 要额外过门禁**。它在 `REVIEW` 集里（不是 `REFUSED`），
   法律上可与 MIT 共存，但会给 `check-licences.mjs` 增加一个需要人工判断的项。
   A 不引入这个问题。
3. **`file_paths.xml` 已经声明了 `cache-path`**——
   现有配置就能支持「从 cache 分享」，不需要碰 AndroidManifest。
4. **让用户选目的地不是缺点**。Tauri 桌面端的导出也是让用户选保存位置；
   统一行为比「安卓悄悄存进 Downloads」更好解释。

### 3.3 已知的坑

- **XLSX 是二进制**，`Filesystem.writeFile` 只收 base64 字符串
  （`encoding` 不传则按 binary 解码，数据必须是 base64）。需要
  `FileReader.readAsDataURL()` 把 Blob 转 base64 —— **大文件会吃内存**。
  本项目导出量级（500 条 × 342 B ≈ 170 KB，xlsx 再多些）不成问题，但要留注释。
- **`Share.share()` 在 Android 上 resolve 的时机**是「选择器打开」，
  不是「用户完成保存」。UI 文案不能说「已保存」，只能说「请选择保存位置」。
- **iOS 上 Share 走 share sheet**，用户可选「存储到文件」——这是 iOS 的标准做法。
- **`Filesystem` 需要 `cap sync`** 才能在原生工程里生效，
  `scripts/package-android.mjs` 里要确认这一步没被跳过。

## 4. v1.3.0 待办

顺序即依赖顺序。每一项都必须带**守卫测试**（决策 #9）。

### T1 · 安卓导出（依赖 §3.4 的验证结果）

- **改**：`src/ui/export.mjs` 的 `downloadFile()` 拆成平台分支；
  新增 `src/ui/native-save.mjs` 封装 Capacitor 侧写入 + 分享
- **依赖**：`@capacitor/filesystem@7.1.8` + `@capacitor/share@7.0.4`
- **守卫**：无真机测不了 → 写一个「平台分支正确性」单测
  （mock `Capacitor.isNativePlatform()`，断言 web 走 `downloadFile`、
  native 走插件路径），**并在本文档记录真机验证的手工步骤**
- **注意**：不引入 `Capacitor` 的静态 import 到 web 路径，
  否则 web bundle 会多一个用不上的依赖。用动态 `import()`

### T2 · 写失败可见

- **改**：`App.jsx` 的保存 effect 检查 `saveHistory` 返回值，置 `saveFailed` state；
  新增一个常驻横幅组件（可复用在 `.topbar` 下方）
- **文案**（中英双份，进 `locales/`）：
  中文「历史已停止保存 —— 存储空间已满或浏览器不允许写入。请立即导出备份。」
  英文 "History has stopped saving — storage is full or blocked. Export a backup now."
- **不可关闭**：这不是提示，是常驻状态。恢复写入后自动消失。
- **守卫**：挂载真 `App`（**必须真 useState，不能用常量 prop**——
  见 [load-save-effect-race-wipes-storage] 的教训），
  store 的 `setItem` 抛异常 → 断言横幅出现；换成正常 store → 断言横幅消失

### T3 · 墓碑上限

- **改**：`src/ui/history.mjs` 的 `saveHistory()`，给 `deletedAt` 记录加计数上限
- **N 取值**：建议 **300**。理由：比 live 上限（500）小，
  但足够覆盖「误删后想起来要恢复」的真实场景；
  300 × 381 B ≈ 114 KB，加上 500 条 live 共约 280 KB，
  离 5 MB 有 18 倍余量。
- **语义**：保留**最近删除**的 N 条。最新的删除最可能被撤销。
- **守卫**：造 N+50 个 tombstone → 断言只留 N 个且留下的是 `deletedAt` 最新的那批；
  另断言 live 记录数不受影响（两个上限独立计数）

### T4 · `persist()` 请求

- **改**：首次成功写入后调 `navigator.storage?.persist?.()`，
  结果存 `state`，供 T2 的横幅引用（denied 时横幅措辞可更强）
- **不要 UI**（决策 #8）：`navigator.storage` 在 Android WebView 上可能不存在，
  要 `?.` 链式降级；结果只做内部状态，不新增设置面板项
- **守卫**：mock `navigator.storage.persist` → 断言在首次写入后**恰好调用一次**
  （不是每次写入都调）；`navigator.storage` 不存在时断言不抛错

### T5 · 免责第 6 条 + iOS 安装文案

- **改 1**：`src/ui/disclaimer.mjs` 加第 6 条
  - 中文：「记录存在本机浏览器里。清理浏览器数据、或用无痕模式会丢失，
    请定期导出 JSON 备份。iOS 上超过 7 天不打开，系统可能自动清掉——
    请先「添加到主屏幕」再使用。」
  - 英文对应
- **改 2**：`src/ui/locales/zh.mjs` + `en.mjs` 的 `install.lead`，
  把真实理由写进去（现状只写了「离线可用」）
- **注意**：iOS 的 7 天规则**不适用于已安装到主屏幕的 Web App**
  （WebKit 官方豁免），所以措辞是「先安装」而不是「装了也会丢」
- **守卫**：断言 `DISCLAIMER_POINTS.length === 6`；
  断言第 6 条的 zh/en 都含「备份」/「backup」关键词；
  断言 `install.lead` 在两语言下都提到数据存续（不能只是「离线可用」）

### T6 · 导出预览增强

现状已有预览（`exportPreview()`，CSV/Markdown/XLSX 走 `openPreview`），
但 **JSON 备份不预览**（[HistoryPanel.jsx:179](src/ui/components/HistoryPanel.jsx#L179) 说明了理由：
JSON 是含已删记录的完整归档，三行预览会误导）。

**这一项的改动**：不推翻那个判断。给 JSON 路径一个**不同的**确认界面——
不是表格预览，而是「这次会带走 N 条记录（含 M 条已删除）」+
「文件大小约 X KB」+ 确认按钮。**数字而非行**，才不构成误导。

- **守卫**：断言 JSON 确认界面对已删记录计数正确；
  断言它的数字与 `toBundle()` 实际产出的条数一致
  （与 `export-preview.test.mjs` 现有那条「预览必须与文件一致」同一原则）

## 6. 环境陷阱（沿用，实测有效）

| 陷阱 | 说明 |
|---|---|
| **Git Bash 裸 `find`** | 命中 Windows `find.exe`，**静默返回空**。用 `git ls-files` 或 node |
| **Bash 工具时区是 GMT** | 系统 +0800，差 8 小时。写日志时间戳会错 |
| **node 的 `/tmp`** | 映射到 `E:\tmp`，不是 Git Bash 的 `/tmp` |
| **GitHub 直连不通** | 全局代理已配 `127.0.0.1:7897` + `http.sslVersion=tlsv1.2`（2026-09-29 zcode 设置），现在 git 直接可用 |
| **`gh api` 路径改写** | Git Bash 会改写路径，需 `MSYS_NO_PATHCONV=1` |
| **Playwright 截图** | 落盘到工作区根的 `.playwright-mcp/`，不是 lab-calc 下的 |
| **`node_modules/@capacitor`** | 被 deny 规则挡住，不能用 `ls`/`grep` 直读；用 `npm view` 查元数据 |
| **Python 控制台 GBK** | 打印非 ASCII 会崩，用 `PYTHONIOENCODING=utf-8` |
