## 3. 架构现状（改动前必须理解的三条线）

### 3.1 元数据字段现在是**编译期常量**

```
src/ui/history.mjs:282   export const META_FIELDS = [experiment, purpose, operator]
src/ui/history.mjs:303   const META_KEYS = META_FIELDS.map(f => f.key)
src/ui/history.mjs:316   setEntryMeta() —— 只接受 META_KEYS 里的 key，未知 key 直接丢弃
src/ui/components/EntryMeta.jsx:31,65,95  直接遍历 META_FIELDS 渲染
src/ui/export.mjs:44     usedMetaFields() —— 从 META_FIELDS 过滤
```

**这是本阶段最大的改动面。** 白名单不是多余的：注释写明「未声明的 key 会导出成无法标注的列」。
所以不能简单删掉校验——要改成**校验「有效模板」**（内置 + 用户定义），而不是一个冻结常量。

### 3.2 记录已经是「标记删除」而非抹除

```
history.mjs:179  clearHistory()  —— map 成 { ...e, deletedAt }
history.mjs:160  visibleEntries / deletedEntries
HistoryPanel.jsx:332  已渲染回收站 + 单条还原 + 批量还原
```

**用户反馈的「误触清空」其实已有防护**（回收站 + 批量还原）。缺的是两点：
1. **当下就能撤**——按下去立刻出一条「已清空 N 条 · 撤销」，而不是让用户自己去找回收站
2. 用户不知道有回收站，所以「全都没了」的第一反应仍然是恐慌

### 3.3 计算层是纯函数、不抛文案

`src/calc/*.mjs` 抛 `CalcError{code, params}`，UI 翻译。**新增的教学可解释性必须遵守这条**：
计算层返回结构化步骤数据，文案在 `locales/` 里。

## 4. 分阶段实施

### 阶段 A —— 记录体验（用户反馈的功能类，优先级最高）

#### A1. 可配置字段模板

新建 `src/ui/field-template.mjs`：

```js
// 内置三段（实验号/用途/操作人）保持 key 不变，保证已有记录不丢
export const BUILTIN_FIELDS = [ ...原 META_FIELDS... ];
export const FIELD_TYPES = ['text', 'number', 'date', 'select'];

export function resolveTemplate(userFields = [])   // 内置 + 用户定义，去重
export function validateFieldDef(def)              // key 合法、label 非空、maxLength 上限
export function addField / updateField / retireField
export function activeFields(template)             // 未被停用的
export function retiredFields(template)            // 停用但仍需给历史值标注
```

关键设计（三条，都有理由）：

1. **停用 ≠ 删除。** 停用的字段保留在模板里（`retired: true`），只从新记录的编辑器里消失。
   理由：老记录还带着这个值，导出时必须有标签，否则导出一个没有列名的列。
2. **`setEntryMeta` 的白名单改为查「有效模板 + 停用字段」**，不是查常量。
   保留原设计意图（不留无法标注的列），同时允许用户自定义。
3. **key 一旦生成不可变**，label 可改。与 `field-labels.mjs` 同一条规则（注释里写明了）。

落点：
- [history.mjs:282-342](lab-calc/src/ui/history.mjs#L282-L342) —— `META_FIELDS` 改为从模板解析
- [EntryMeta.jsx](lab-calc/src/ui/components/EntryMeta.jsx) —— 渲染解析后的模板
- [CustomisePanel.jsx](lab-calc/src/ui/components/CustomisePanel.jsx) —— 新增「记录字段」区：增/改/停用/排序

#### A2. 记录前预设默认值

模板字段带 `default`，新记录自动带上。场景：一个用户整周都填同一个「操作人」和「用途」。

落点：`addEntry()` 调用点（`App.jsx`），默认值来自模板。

#### A3. 删除防呆

- **撤销条**：`clearHistory` / `removeEntry` 后立刻出 `role="status"` 的条，带「撤销」按钮，8s 后自动消失
- 保留现有回收站（它是长久兜底，不是替代）
- 单条删除也走同一套（现在是直接标记，没有即时反馈）

落点：[HistoryPanel.jsx:214-220](lab-calc/src/ui/components/HistoryPanel.jsx#L214-L220)、`App.jsx` 的 `clear`/`remove` 回调

#### A4. 迁移与兼容

- v1 记录（无 `meta`）继续可用 —— 现有 `normalise` 已处理，不回归
- 模板存储加 schema 版本号，从第一版就写（照 `BUNDLE_FORMAT` 的先例）
- **测试**：老记录 + 新模板 = 不丢值；停用字段的值仍能导出

### 阶段 B —— 导出优化

#### B1. 配方卡导出（核心改进）

现在的导出是**原始数据**（输入列 + 结果列）。科研场景真正要的是**照着能配的配方**：

```
配制 0.5 mol/L NaCl 溶液 500 mL
────────────────────────────────
1. 称取 NaCl 固体 14.61 g
2. 转移至 500 mL 容量瓶
3. 加去离子水至刻度，摇匀
```

数据结构：`src/calc/` 各计算返回可选的 `procedure: [{step, value, unit}]`；导出层渲染成 Markdown/文本。
**不是所有计算都要有**——先给称量、稀释、缓冲液、梯度稀释四个「照着做」的。

#### B2. 出处与版本

每份导出头部写：应用版本、导出时间、记录条数、模板字段清单、`BUNDLE_VERSION`。
理由：一份贴进论文附录的表格必须能说清它是哪个版本导出的。

#### B3. 导出前预览

在下载前显示前 3 行 + 列清单，确认再下。现在是从菜单点下去直接下载，没有回看机会。

#### B4. 列选择覆盖模板字段

`ColumnPicker` 现在从 `META_FIELDS` 推可用列，改为从**实际用到的字段**推（含停用字段）。

落点：[export.mjs:44](lab-calc/src/ui/export.mjs#L44) `usedMetaFields`、`ColumnPicker`

#### C2. 演示级动效（用户明确要「明显炫技」）

| 动效 | 落点 | 演示价值 |

### 阶段 D —— 教学亮点

#### D1. 预置实验场景（性价比最高）

每个标签页 2-3 组真实场景，点一下填满输入并算出。数据放 `src/calc/scenarios.mjs`，
纯数据、可测（断言每组场景都能算出结果且不抛错）。

示例：「配制 PBS 缓冲液」「稀释抗体母液 1:1000」「0.1 M 乙酸滴定曲线」。

评审打开就有东西看 —— 不用自己编数据，这是**四类评审都能感知**的一项。

#### D2. 计算过程可展开

**这是最需要控制范围的一项。** 全部 13 类计算都做推导 = 一周做不完。

建议范围（10 个教学价值最高的）：
称量配制、稀释、缓冲液 H-H、pH 活度校正、滴定曲线电荷平衡、反应配平、
Nernst、Beer–Lambert、依数性、不确定度传播。

数据形状（计算层返回，UI 渲染文案）：
```js
derivation: [
  { eq: 'n = c · V', subst: 'n = 0.5 × 0.5', result: '0.25 mol' },
  { eq: 'm = n · M', subst: 'm = 0.25 × 58.440', result: '14.61 g' },
]
```
`eq` 是公式（不翻译），`subst`/`result` 是数值，标签走 `locales/`。

已有的好例子可复用：README 里展示的滴定曲线电荷平衡推导就是这个形状。

#### D3. 结果分享卡片

把一次计算渲成一张 PNG（SVG → canvas → blob），含：摘要、关键结果、公式、应用名与版本。
纯前端零依赖（项目已有手写 `xlsx.mjs` 的先例，气质一致）。

## 5. 执行顺序与理由

```
A 记录体验  →  B 导出  →  D 教学亮点  →  C 视觉动画  →  E 发布门面  →  F 全量复查
```

**为什么这个顺序：**

- **A 最先**：用户反馈的功能类痛点，且它改的是数据模型（模板），后面的 B/D 都要读这个模型
- **B 紧跟 A**：导出直接依赖模板（列选择、出处），一起改一次测
- **D 在 C 前**：教学亮点会新增 UI 元素（场景按钮、推导展开区），先定下来再统一做动画，
  否则动画要做两遍
- **C 在 E 前**：动画改完要重新截图，截图是 README 的素材
- **E 最后**：README 里的测试数、主题数、截图全部依赖前面完成
- **F 收尾**：全量 bug 复查 + 20 标签页浏览器实测

**关于「24 小时无间断」**：我无法真的连续跑 24 小时不中断。实际做法是**分段长跑**，
每个阶段结束给你一份「改了什么 / 测试数 / 截图 / 遗留」的汇报，你可以随时打断或调整。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| **keystore 丢失 = 永远无法更新已装用户** | 生成后第一件事：提示你异地备份；`.jks` 与密码绝不入库 |
| 模板改动打坏已有记录 | 迁移测试先行（TDD）；内置三段 key 不变；停用而非删除 |
| 导出出现「无标签的列」 | 保留停用字段定义，导出时仍能标注 |
| D2 推导范围失控 | 明确圈定 10 项；其余不做，不假装 |
| `check-doc-numbers` 拦提交 | README 放最后写；每改一次测试数就同步一次 |
| 动画拖慢移动端 | 每项动画在移动端视口实测；`prefers-reduced-motion` 全覆盖 |
| 一周做不完四组 | 阶段边界可截断：A+B 是必须，D 是加分，C 是门面。到点没做完的**如实汇报**而不是硬塞 |
